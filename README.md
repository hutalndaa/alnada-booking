# أكواخ الندى - نظام الحجوزات الكامل

## المكدس التقني
Next.js 14 (App Router) + Supabase (PostgreSQL + Auth) + Tailwind CSS

## الأدوار
- **مالك (owner)**: كل الصلاحيات — إدارة الأكواخ، الأسعار والخصومات، الموظفين، وكل الحجوزات
- **مشغل (operator)**: يشوف الحجوزات، يأكد دفع يدوي (كاش)، يلغي حجز — بدون وصول لإدارة الأكواخ/الأسعار/الموظفين
- **عميل**: يتصفح ويحجز بدون تسجيل دخول

## خطوات التشغيل

### 1) إعداد Supabase
1. أنشئ مشروع على https://supabase.com
2. من SQL Editor نفّذ ملف `alnada_schema.sql` كامل (يشمل الجداول + RLS + جدول الموظفين)
3. من Authentication → Providers، تأكد إن Email مفعّل
4. من Authentication → Settings، عطّل "Allow new users to sign up" (التسجيل يتم فقط عن طريق المالك من لوحة التحكم، مو تسجيل عام)
5. من Project Settings → API انسخ: Project URL, anon key, service_role key

### 2) إنشاء أول حساب مالك (يدوياً - مرة واحدة فقط)
من Authentication → Users في Supabase، أنشئ مستخدم يدوياً (بريد + كلمة مرور)،
ثم من SQL Editor نفّذ:
```sql
insert into staff (id, full_name, role)
values ('USER_ID_من_الخطوة_السابقة', 'اسمك', 'owner');
```
أي حساب مالك أو مشغل بعد كذا، تقدر تنشئه من داخل لوحة التحكم (/admin/staff) بدون رجوع لـ Supabase.

### 3) تشغيل المشروع محلياً
```bash
npm install
cp .env.example .env.local
# عبّي القيم من خطوة 1
npm run dev
```
- الموقع للعملاء: http://localhost:3000
- دخول الموظفين: http://localhost:3000/login
- لوحة التحكم: http://localhost:3000/admin

## الحالة الحالية
- ✅ عرض الأكواخ + حجز بالساعة مع حساب السعر والخصم تلقائياً
- ✅ منع تعارض الحجوزات ذرياً على مستوى قاعدة البيانات (Race-safe)
- ✅ فاصل تنظيف بين الحجوزات (قابل للتعديل لكل كوخ)
- ✅ حجز مؤقت بمهلة قبل الإلغاء التلقائي
- ✅ صفحة دفع تجريبية (Mock) - جاهزة تُستبدل ببوابة حقيقية
- ✅ تسجيل دخول موظفين + صلاحيات (مالك/مشغل) عبر RLS و API Guards
- ✅ لوحة تحكم: الحجوزات (تأكيد دفع يدوي/إلغاء)، الأكواخ، الأسعار والخصومات، الموظفين
- ⬜ Job مجدول (Supabase Cron) يحوّل الحجوزات المنتهية المهلة إلى `expired` تلقائياً
- ⬜ تكامل بوابة دفع حقيقية

## ربط بوابة دفع فعلية لاحقاً
كل التصميم مبني عشان هذي الخطوة تكون بسيطة:
1. عدّل `lib/payment.ts` → دالة `createPaymentIntent` تستدعي API البوابة المختارة وترجع رابط الدفع الحقيقي بدل `/pay/[id]`
2. بوابة الدفع (Moyasar/Tap/PayTabs) ترسل Webhook بعد نجاح الدفع → وجّهيه لـ `app/api/bookings/[id]/confirm/route.ts` (موجود وجاهز، فقط أضف التحقق من توقيع الطلب حسب توثيق البوابة)
3. احذف صفحة `/pay/[id]/page.tsx` التجريبية بعد التكامل الفعلي

الباقي (منع التعارض، الخصومات، الصلاحيات، لوحة التحكم) ما يتأثر أبداً بتغيير بوابة الدفع.
